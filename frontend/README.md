# Вместе — frontend совместного календаря

React + TypeScript + Vite. Вход и регистрация сохраняют исходное оформление.
После входа доступны календарь по дням, создание и список событий, друзья,
входящие и исходящие заявки, профиль и удаление своего аккаунта с подтверждением.
Иллюстрация календаря на странице входа остаётся примером.

## Запуск

Из каталога `frontend`:

```sh
npm install
npm run dev
```

Открыть адрес из вывода Vite, обычно `http://localhost:5173`.
Backend должен работать на `http://127.0.0.1:8000` с подготовленной БД.
Vite проксирует `/api/*` на backend, убирая `/api`; локально CORS не требуется.

```sh
npm run build
npm run lint
npm test
npm run test:integration
```

Для тестов нужен Node.js 22.18+ с поддержкой TypeScript без компиляции.
Интеграционный тест использует зависимости существующей `backend/.venv`
и временную базу в памяти. Путь к Python можно задать через `BACKEND_PYTHON`.
Файлы backend и пользовательская база при тестировании не изменяются.

## Авторизация и текущие ограничения

- Регистрация: POST `/users`, JSON `{ login, email, password }`.
- Вход: POST `/token_test`, форма `username`, `password`.
- Токен хранится в `sessionStorage` под ключом `calendar_access_token`.
  Все защищённые запросы отправляют Bearer-токен; пароли не сохраняются.
- Профиль читается через GET `/users/me/`, в том числе после перезагрузки.
  HTTP 401 возвращает пользователя ко входу. При сетевой ошибке доступна
  повторная попытка без потери токена.
- События отображаются по датам: backend пока теряет время при сохранении.
- Друзья добавляются по ID; заявки без доступного имени отображаются по ID.
- Изменение профиля, приглашение участников, редактирование и удаление событий
  недоступны из-за неисправного или отсутствующего API.
- Проверка пароля от восьми символов — правило интерфейса регистрации.
  Сервер должен самостоятельно проверять допустимость входных данных.

Полная таблица эндпоинтов, результаты проверки и необходимые изменения backend
собраны в [BACKEND_INTEGRATION.md](./BACKEND_INTEGRATION.md).

## Развёртывание

В production настройте reverse proxy `/api` на backend с удалением префикса.
Прокси `vite.config.ts` работает только с сервером разработки.
Альтернатива — задать `VITE_API_URL` перед сборкой, как в `.env.example`.
Для другого origin backend должен разрешать CORS. Значения `VITE_*` публичны;
секреты в них размещать нельзя.
