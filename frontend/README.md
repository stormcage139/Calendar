# Вместе — frontend совместного календаря

React + TypeScript + Vite. После входа открывается существующий Planner с данными
FastAPI: события с приглашениями и голосованием за дату, календарь, друзья, заявки
и профиль. В интерфейсе есть только возможности с рабочим API.

## Запуск

Из каталога `frontend`:

```sh
npm install
npm run dev
```

Backend должен работать на `http://127.0.0.1:8000` с подготовленной БД.
Vite проксирует `/api/*` на backend, убирая `/api`; локально CORS не требуется.

```sh
npm run build
npm run lint
npm test
npm run test:integration
```

Для тестов нужен Node.js 22.18+ с поддержкой TypeScript без компиляции.
Интеграционный тест использует зависимости существующей `backend/.venv`
и временную базу в памяти. Путь к Python можно задать через `BACKEND_PYTHON`.
Backend и пользовательская база при тестировании не изменяются.

## Подключение

- Регистрация: `POST /register`, JSON `{ login, email, password }`.
- Вход: `POST /login`, JSON `{ login, password }`.
- Профиль и восстановление сессии: `GET /me`.
- События: `GET /events/`, `POST /events/`.
- Друзья и заявки по введённому ID: `GET /friends`, `GET /friends/requests`,
  `POST /friends/{id}`, `DELETE /friends/{id}`.
- Изменение своего профиля: `PATCH /users/{id}`. После сохранения нужен повторный
  вход, поскольку токен содержит логин. API требует логин, email и пароль вместе.
- Удаление своего аккаунта: `DELETE /users/{id}`, с подтверждением логином.
- Проверка соединения в профиле: `GET /ping`.

Токен хранится в `sessionStorage` под ключом `calendar_access_token`.
Защищённые запросы отправляют Bearer-токен; пароли не сохраняются.
HTTP 401 возвращает ко входу. При сетевой ошибке профиля можно повторить запрос
без потери токена. Прямой переход на `#calendar` также требует входа.
Списки обновляются после действий и при возвращении фокуса в окно; ошибки загрузки
показываются с повторной попыткой.

События сортируются и группируются по дате дедлайна: backend хранит дату без времени.
Поиск, переключение месяцев и выбор дня выполняются на загруженных событиях.
Значения участников, голосов и статусов, отсутствующие в API, не подменяются примерами.

Подробности контрактов и ограничения: [BACKEND_INTEGRATION.md](./BACKEND_INTEGRATION.md).

## Развёртывание

В production настройте reverse proxy `/api` на backend с удалением префикса.
Прокси `vite.config.ts` работает только с сервером разработки.
Альтернатива — задать `VITE_API_URL` перед сборкой, как в `.env.example`.
Для другого origin backend должен разрешать CORS. Значения `VITE_*` публичны;
секреты в них размещать нельзя.
